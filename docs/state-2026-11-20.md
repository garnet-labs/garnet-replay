## Operator commands

Use Node 20+ and `gh` from this Garnet-owned checkout. No runtime dependency
installation is needed. Map the provisioned GitHub PAT explicitly; Garnet API
tokens do not authenticate GitHub. Never print tokens.

```sh
export GH_TOKEN="$GARNET_LABS_GITHUB_PAT"
npm test
node bin/replay.mjs --help
node bin/replay.mjs verify https://github.com/garnet-labs/E2B/pull/93
node bin/replay.mjs verify https://github.com/garnet-labs/litellm/pull/153
node bin/replay.mjs verify https://github.com/garnet-labs/nodejs-goof/pull/4
```

The last command is expected to exit 1 for residue at this snapshot. These
commands do not write forks or ledgers. To use an existing authenticated `gh`
session instead, set `GH_TOKEN=$(gh auth token)` without echoing it.

Commands with local writes (not read-only audit probes):

```sh
node bin/replay.mjs status             # writes out/STATUS.md
node bin/replay.mjs card https://github.com/garnet-labs/E2B/pull/93
node bin/replay.mjs decide https://github.com/garnet-labs/E2B/pull/93
node bin/replay.mjs rows docs/triage-manifest.json --out out/rows
```

`card` writes a card and updates `targets/e2b.json` through `saveTarget`.
`decide` writes `out/e2b/pr-93-decision.json`, not a target ledger, and exits
0/1/2 for merge/hold/undeterminable. It is not `verify`. `rows` writes its
rows, table and research-note skeleton; the operator supplies assessments.
Never restore ledger rows by hand after a probe.

Third-party replay execution belongs on the GitHub-hosted `replay` workflow,
not local `--work` checkouts. For an authorized manual start, use
`gh workflow run replay.yml -f action=start -f slug=<slug> -f number=<upstream-pr> -f plan=<prepare-run-id> -f request=<correlation-id>`.
This dispatch writes GitHub state: it is not a read-only check. Hosted publishing
needs `REPLAY_FORK_TOKEN`; fleet repair needs `FLEET_GITHUB_TOKEN`.
